# Карта соединений роутера OpenWrt

Живая карта соединений роутера на OpenWrt: куда ходят устройства дома, что делает сам роутер и кто
подключается к нему снаружи. Данные читаются с роутера по ubus поверх HTTP — напрямую или через
HTTP-прокси. На роутер ставится один скрипт из двух строк; сам сервис работает на любой машине, которая
видит роутер: в домашней сети или за прокси.

Только Python 3.9+ со стандартной библиотекой; работает на Linux, macOS и Windows. Проверено на Xiaomi AX3000T с OpenWrt 23.05.5.

## Настройка роутера

Пошаговая инструкция — в [ROUTER-SETUP.md](ROUTER-SETUP.md). Коротко: на роутер кладётся скрипт из двух
строк (он отдаёт таблицу соединений), файл прав «только чтение» и пользователь `map` с паролем. Нужны
пакеты `uhttpd-mod-ubus` и `rpcd-mod-file` — они ставятся вместе с LuCI.

Проверить настройку с машины, где будет работать карта: `python3 check.py` (Windows: `check.bat`).
Проверка входит на роутер и делает каждый вызов, который нужен карте; все строки должны быть `[ok]`.

## Запуск

### Linux, macOS

```
cp .env.example .env        # адрес роутера, пользователь, пароль, прокси
./start.sh                  # скачать недостающие базы и запустить; root не нужен
./start.sh --update         # сначала обновить базы до свежего месяца
```

### Windows

1. Установите Python 3.9 или новее: https://www.python.org/downloads/ (отметьте «Add python.exe to PATH»)
   или командой `winget install Python.Python.3.12`. Других пакетов не нужно.
2. Скопируйте каталог проекта целиком. Скопируйте `.env.example` в `.env` и впишите адрес роутера,
   пользователя и пароль. Файл удобно править Блокнотом; сохраняйте в UTF-8.
3. Двойной щелчок по `check.bat` — проверка связи с роутером и прав. Все строки должны быть `[ok]`.
4. Двойной щелчок по `start.bat` — запуск. При первом запуске скачиваются базы (~95 МБ) и около минуты
   строится их кэш. Окно не закрывайте: пока оно открыто, карта обновляется. `start.bat --update` —
   сначала обновить базы.
5. Если в `.env` задано `http_host=0.0.0.0`, Защитник Windows спросит разрешение для Python: разрешите
   для частной сети. При `127.0.0.1` (по умолчанию) карта доступна только на этой машине, и вопроса нет.

На Windows нет системной копии реестра OUI: `oui.txt` скачивается с сайта IEEE. Если сайт недоступен,
положите `oui.txt` в каталог `oui/` вручную; без него устройства останутся без производителя.

### Адрес карты

Сервис печатает адрес карты (по умолчанию http://127.0.0.1:8787). Первый запуск скачивает базы
(~95 МБ) и около минуты строит их кэш. В журнале должны появиться строки `config: … WAN …` и затем
`poll: N connections`. `login failed` — неверный пароль или нет пользователя `rpcd`; `HTTP 5xx from the
proxy` — прокси не видит роутер по этому адресу.

Через прокси роутер обычно виден только по адресу LAN: firewall OpenWrt не пускает к веб-интерфейсу с WAN.

Авторизации у карты нет: при `http_host=0.0.0.0` её видит вся локальная сеть.
Для браузера нужен интернет: шрифты, d3 и контуры карты грузятся с CDN.

## Настройки: `.env`

| Ключ | По умолчанию | Что это |
|---|---|---|
| `router_url` | — | адрес роутера: `http://192.168.1.1`; можно `https://`, сертификат не проверяется |
| `username`, `password` | — | пользователь `rpcd` из настройки роутера |
| `proxy` | пусто | `host:port` HTTP-прокси, если роутер доступен только через него |
| `wan_interface` | `wan` | логический интерфейс OpenWrt, который смотрит в интернет |
| `poll_interval` | `15` | секунд между опросами (минимум 5) |
| `config_interval` | `300` | секунд между перечитыванием интерфейсов, firewall, портов и файла имён |
| `http_host`, `http_port` | `127.0.0.1`, `8787` | где слушает карта |
| `public_ip` | пусто | внешний адрес; пусто — адрес WAN, а если он серый, запрос к ifconfig.me через тот же прокси; `off` — не спрашивать |
| `location` | пусто | `широта,долгота` роутера, если DB-IP не знает место внешнего адреса |
| `names_file` | `names.conf` | свои имена устройств и внешних адресов, формат как в `linux-api` |

Любой ключ, кроме `username` и `password`, можно переопределить переменной окружения в верхнем регистре
(`POLL_INTERVAL=10 ./start.sh`); для пользователя и пароля — `ROUTER_USER` и `ROUTER_PASSWORD`.

## Что читается с роутера

Каждые `poll_interval` секунд: нагрузка и память (`system info`, `/proc/stat`), счётчики устройств
(`network.device status`), соседи (`ip neigh`), аренды DHCP, клиенты Wi-Fi (`iwinfo assoclist`), журнал
(`logread`) и вся таблица соединений через `/usr/libexec/map-conntrack`.

Каждые `config_interval` секунд: модель и версия (`system board`), интерфейсы и адреса
(`network.interface dump`), внешний адрес, слушающие порты (`netstat -lntup`), конфигурация firewall
(`uci get firewall`), `/etc/hosts` роутера и файл имён.

Один опрос — около десятка HTTP-запросов; через прокси он занимает несколько секунд.

## Особенности

- **Скорости отдельных соединений не показываются.** Счётчики байт conntrack на роутере ненадёжны: у части
  живых соединений они нулевые или сбрасываются (так делают мониторы трафика вроде nlbwmon). Вместо этого
  активность определяется по таймеру записи conntrack: каждый пакет его обновляет, и если между опросами
  таймер вырос — соединение живое, по дуге бегут точки. Толщина дуг и сортировка — по числу соединений.
- **Скорость канала точная**: считается по счётчикам WAN-интерфейса.
- **Потока событий нет**, только опрос: соединение, которое открылось и закрылось между двумя опросами, не видно.
- **Имена устройств**: `names.conf`, затем имя из аренды DHCP, `/etc/hosts` роутера, производитель по MAC.
- **Порты из интернета**: слушающие процессы и вердикт firewall по конфигурации OpenWrt — зона WAN, её
  политика входа, правила с `src wan` и пробросы (`redirect`). Правила, добавленные мимо `uci`
  (собственные таблицы nftables, `firewall.user`), не учитываются. Порты DHCP-клиентов роутера (68, 546) не показываются.
- **Кто на роутере**: открытые сессии SSH и входы за час — dropbear и LuCI из `logread`. Журнал роутера
  хранит только последние строки, после перезагрузки он пуст.
- **Сканы с интернета** обычно не видны: firewall OpenWrt отбрасывает их до записи в conntrack.

## Файлы

- `server.py` — HTTP-сервер: страница, `/api/state`, `/api/events`.
- `collector.py` — опрос роутера, сравнение снимков, активность по таймеру, входящие за час.
- `ubus.py` — клиент ubus поверх HTTP с прокси и повторным входом.
- `router.py` — чтение данных роутера: система, интерфейсы, соседи, DHCP, Wi-Fi, порты, firewall, входы.
- `conntrack.py` — разбор строк таблицы соединений.
- `names.py`, `classify.py`, `geo.py`, `oui.py` — имена, категории, место и организация по IP, производитель по MAC.
- `config.py`, `fetch_data.py`, `start.py` — настройки, базы, запуск на любой системе.
- `start.sh`, `start.bat` — обёртки для Linux и Windows.
- `check.py`, `check.bat` — проверка настройки роутера.
- `ROUTER-SETUP.md` — инструкция по настройке роутера.
- `web/` — карта.
